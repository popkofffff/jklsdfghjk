# HotShift — ловец горячих смен Ozon Job

Android-приложение (Kotlin + Jetpack Compose), которое помогает забирать «горячие»
смены на Ozon Job в момент их появления (обычно около **06:00** по местному времени).

Возможности:

1. **Выбор дня** — горизонтальная лента на 14 дней вперёд.
2. **Время смены** — длительность 4/6/8/12 ч + выбор предпочтительного времени начала.
3. **Быстрое бронирование**:
   - кнопка «Забронировать» на каждом слоте;
   - режим **«Охота»**: фоновый сервис заранее (за 8 секунд) встаёт на 06:00,
     опрашивает слоты каждые 300 мс и сразу бронирует первый подходящий,
     даже если приложение свёрнуто. Результат — в уведомлении.

## Сборка

1. Установи Android Studio (Koala или новее), JDK 17.
2. `File → Open` → папка проекта. Android Studio сама подтянет Gradle
   (нужна версия 8.7+).
3. Поставь недостающее: Android SDK 34.
4. `Build → Build APK(s)` или `./gradlew assembleDebug`.

## Подключение реального API Ozon Job (важно!)

У Ozon Job **нет публичного API**, поэтому адреса запросов нужно снять с трафика
официального приложения «Озон Работа» (`ru.ozon.hire`). Все настройки собраны
в одном файле:

```
app/src/main/java/com/hunter/ozonjob/data/api/ApiConfig.kt
```

Порядок:

1. Поставь HttpCanary (или Charles Proxy на ПК) и включи перехват HTTPS.
2. Открой приложение Ozon Job и сделай по порядку:
   - вход по номеру телефона → увидишь запрос на отправку SMS и запрос
     проверки кода (в ответе придёт токен);
   - вкладка бронирования смен (выбери день и длительность) → увидишь запрос
     списка слотов;
   - нажми «Забронировать» → увидишь запрос брони.
3. Перепиши в `ApiConfig.kt`:
   - `HOST` — базовый адрес сервера;
   - `PATH_SEND_CODE`, `PATH_VERIFY_CODE`, `PATH_SLOTS`, `PATH_BOOK` — пути;
   - при необходимости — имена полей в моделях
     `app/src/main/java/com/hunter/ozonjob/data/api/OzonJobApi.kt`
     (`@SerialName(...)`), ответ сервера увидишь в том же перехвате.
4. Если сервер проверяет User-Agent — подставь реальный из перехвата в
   `ApiConfig.USER_AGENT`.

Парсинг слотов сделан «терпимым» (`ignoreUnknownKeys`, опциональные поля и
альтернативные ключи `slots/items/available/data`), так что небольшие отличия
схемы не уронят приложение.

### Если сервер использует SSL-pinning

HttpCanary не увидит трафик при pinning. Понадобится Frida/objection-скрипт
отключения pinning или `mitmproxy` с подменённым CA. Если и это не сработает —
добавим обход pinning прямо в `ApiFactory.create()`.

## Как работает горячая бронь

```
05:59:52  сервис встаёт, первый «разогревающий» опрос
06:00:00  ~3 запроса в секунду на слоты (POLL_INTERVAL_MS = 300 мс)
…         как только появился нужный слот → мгновенный POST брони
          если сервер вернул ошибку — до 8 повторов по 120 мс
06:03:00  если слотов так и не было — окно охоты закрывается
```

Эти параметры тоже в `ApiConfig.kt`.

## Структура проекта

```
app/src/main/java/com/hunter/ozonjob/
├── MainActivity.kt            — вход в UI, запрос разрешений
├── HotShiftApp.kt             — сервис-локатор (токен, репозиторий, движок охоты)
├── data/
│   ├── ShiftSlot.kt           — модель слота смены
│   ├── OzonJobRepository.kt   — вход, загрузка слотов, бронь с ретраями
│   ├── api/ApiConfig.kt       — ВСЯ конфигурация API в одном месте
│   ├── api/OzonJobApi.kt      — Retrofit-интерфейс + DTO
│   └── prefs/TokenStore.kt    — токен и настройки на устройстве
├── booking/
│   ├── HuntEngine.kt          — цикл ожидания 06:00 → жёсткий опрос → бронь
│   └── HuntService.kt         — foreground-сервис + уведомления о статусе
└── ui/
    ├── HotShiftViewModel.kt   — состояние экранов
    ├── Screens.kt             — вход, день/время, слоты, охота (Compose)
    └── theme/Theme.kt
```
